# GOTCHAS — Form Lock

Non-obvious traps. Workspace-wide gotchas: [../../../docs/GOTCHAS.md](../../docs/GOTCHAS.md).

- **Two patch classes, two `PatchAll` calls.** `harmony.PatchAll(typeof(X))` patches only the
  annotations in type `X`. After the 2026-08-22 split, `Plugin.Awake` must call it for **both**
  `FormRetentionPatches` and `PickupStutterPatches`; drop one and that whole feature silently stops
  patching with no error. `FormProtection` has no Harmony annotations and is not registered.

- **`_savedPickup*` is a single-slot sentinel, not reentrant.** `PickupStutterPatches` saves the
  pickup timers in `OnActivate` and restores them in `OnDeactivate` via two static floats
  (`-1f` = "no save in flight"). It assumes one pickup state at a time. Fine for the single-player
  flow; don't assume it survives overlapping pickup states.

- **`GameInventory.TryGrabPreviousGrabbedItem` refuses to re-equip Form tools.**
  (`UseType == ToolUseType.Form → return false`.) The whole shipped fix leans on this: skip the
  `TryGrabNone` unequip and the later restore becomes a harmless no-op. If a game update changes
  that method, the fix's assumption breaks.

- **Never redistribute game assemblies.** `Vampire.Runtime.dll`, `Chicken.Utilities`, UnityEngine,
  BepInEx, 0Harmony are all `Private=false` / `<Private>false</Private>` — the game and BepInEx ship
  their own copies. Decompiled game code must never be committed (see `.gitignore` `decompiled/`).

- **`Directory.Build.props` and `pack.ps1` are workspace-synced canonicals.** They're generated by
  `../../tools/sync-mod-files.ps1`; edit the workspace source, not the copies here, or the next sync
  overwrites your change.

- **Dev deploy path ≠ release layout.** `dotnet build` deploys to
  `plugins/MoonlightPeaksMods/FormLock/` (keeps hand-built DLLs clear of Vortex); `pack.ps1` builds
  `SkipDeploy=true` and lays the zip out as `plugins/FormLock/` for players. Don't conflate them.

- **A new code default doesn't reach an existing `.cfg`.** BepInEx keeps existing values; changing a
  default in code only affects a freshly-generated config file. To test a new default on a running
  install you must also hand-edit the live `.cfg`.

- **Build warnings MSB3277 are benign.** The game ships multiple copies of some transitive deps
  (Google.Apis.*, etc.); the reference-conflict warnings are expected. Build is clean at 0 errors.
